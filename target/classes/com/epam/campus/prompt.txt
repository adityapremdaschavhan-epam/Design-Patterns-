💻 Step-by-Step: Implement Singleton DriverManager (Easy & Industry Style)
Step 1: Create Singleton Class
Plain Text
public class DriverManager {
    private static DriverManager instance;
    private WebDriver driver;
    // Private constructor (prevents external object creation)private DriverManager() {}
    // Global access pointpublic static DriverManager getInstance() {
        if (instance == null) {
            instance = new DriverManager();
        }
        return instance;
    }
    // Driver initializationpublic void initDriver() {
        if (driver == null) {
            driver = new ChromeDriver();
        }
    }
    public WebDriver getDriver() {
        return driver;
    }
    public void quitDriver() {
        if (driver != null) {
            driver.quit();
            driver = null;
        }
    }
}


Step 2: Use it in Your Test (Real Usage)
Plain Text
public class LoginTest {
    @BeforeMethodpublic void setup() {
        DriverManager.getInstance().initDriver();
    }
    @Testpublic void testLogin() {
        WebDriver driver = DriverManager.getInstance().getDriver();
        driver.get("https://example.com");
        System.out.println("Login Test Executed");
    }
    @AfterMethodpublic void tearDown() {
        DriverManager.getInstance().quitDriver();
    }
}


🔥 Why this is a TRUE industry scenario (not a textbook example)
Because in real automation frameworks:
WebDriver is a shared expensive resource
Needs centralized control
Should not be randomly instantiated
Must be reusable across tests
Singleton solves:
Resource management
Code duplication
Framework consistency
⚠️ VERY IMPORTANT (This will impress your SME)
Real Industry Twist:
Pure Singleton ❌ is NOT ideal for parallel execution.
Because:
One driver instance
Multiple threads
Tests will clash
So industry evolves this to:
Singleton + ThreadLocal (Advanced Framework Design)
But for:
Beginner frameworks
Sequential execution
Learning architecture
Your Singleton implementation is 100% valid.
